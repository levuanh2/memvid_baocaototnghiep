# 09 — Redesign Options (Phase 10, Claude — Audit Lead)

Baseline: `main` @ `4f228ef9d1e34f8bac59f37a3792fc859400cb64`. Built from the adjudicated master matrix in `08-independent-agy-review.md` §5 (UX-ADJ-001 through UX-ADJ-020) and the duplication matrix in `05-duplication-matrix.md`. These are proposed directions, not implementation yet — nothing here has been built.

## Framing: what's actually broken vs. what's actually good

Three independent audits (visual, usability/a11y, and an unbiased architecture review that worked alone first) converged on the same core diagnosis: **StudyMap's engineering quality is high — the fragmentation is structural and historical, not a sign of sloppy work.** Modal.jsx's focus trap, PanelDivider's keyboard resize, the Quiz flow's accessibility, the hand-tuned dark mode, zero Framer Motion bloat, and the connector/export pipeline we hardened earlier this session are all genuinely above-average. The two real P0s (missing `/app/study` nav link, MindMap toolbar occlusion) and the P1 identity seams (forest-green selection ring on a blue interface, two incompatible map engines) are the visible scar tissue of **three sequential, individually-reasoned redesign/feature rounds that were never fully closed out**: "Phòng Đọc" (seal-red) → attempted "Paper & Graphite" (forest/bronze, partially implemented) → reverted to "Learning Canvas Blue" (`#126CF2`, current). Any option below has to finish that interrupted migration, not add a fourth system on top of it.

## Option A — Conservative refinement

**Keep the current structure. Fix the confirmed defects and finish the interrupted blue migration. No new information architecture.**

- **Visual identity**: Finish the blue migration exactly where it stopped. Point `mindElixirTheme.js`'s `--selected`/`--accent-color` at `var(--accent)` instead of the leftover `var(--forest)` (UX-ADJ-009). Replace `AccountMenu.jsx`'s hardcoded seal-red hex with the token (UX-ADJ-010 equivalent). Declare the missing `--font-display`/`--font-mono` tokens (UX-ADJ-012). Fix the two WCAG contrast failures — dark-mode primary CTA text (2.77:1 → UX-ADJ-005) and muted copy (2.89–3.43:1 → UX-ADJ-006) — by darkening/brightening the existing tokens, not inventing a new palette.
- **Navigation model**: Unchanged two-tab-plus-library structure. Just make it reachable: render the actual `<Link to="/app/study">` the code comment already claims exists (UX-ADJ-001), relabel the ambiguous "StudyMap" header dropdown to "Công cụ học" (UX-ADJ-019) and add a real, separate, visible entry point to the study library.
- **Key layout changes**: Re-anchor the MindMap toolbar or the Knowledge Inspector overlay so Export/Appearance/Overflow are never physically covered when a node is selected (UX-ADJ-002). Convert `StudyBreadcrumb` spans to real links (UX-ADJ-013). Add `inert`/unmount to the closed mobile source drawer so it drops out of tab order (UX-ADJ-010 wording in the matrix — mobile drawer tab-order leak). Bump the two undersized mobile touch targets to ≥44px (UX-ADJ-011).
- **Advantages**: Lowest risk, fastest to ship, directly closes both P0s and every P1/P2 color-and-token defect with no architectural change. Every fix maps to a single file or a shared primitive (Modal.jsx-style leverage).
- **Disadvantages**: Does not address the two-map-engine schism (UX-ADJ-008) or the 823-control repeated-card library (UX-ADJ-007) — the user's "accumulated patches" complaint about MindMap/Export Studio and the "excessive clutter" complaint about the library remain unsolved. The product still feels like two apps stitched together, just with consistent colors.
- **Cost/complexity**: Low. Each item in `08`'s master matrix already lists a migration risk; everything in this option is tagged Low or Medium.
- **Reuse of existing code**: ~100%. No component is replaced, only retinted/rewired.
- **Responsive strategy**: Fix the measured violations (touch targets, drawer tab order, Export Studio mobile clipping UX-ADJ-015, StudyMap mobile crop UX-ADJ-016) in place.
- **Accessibility strategy**: Fix the four concrete a11y bugs found (Command Palette focus hijack UX-ADJ-003, blank ghost state UX-ADJ-004, desktop Escape ignored UX-ADJ-014, mobile drawer tab-order leak) without touching the otherwise-strong a11y baseline already documented (Modal, PanelDivider, Quiz flow).
- **Risk**: Low across the board — every item is isolated, already has a file:line target, and none touches the guarded invariants in `08` §6 (WorkspaceContainer mounting, useStudyContext's dual identity, ContextPanelCloseButton's dual-mode lifecycle).

## Option B — Balanced workspace redesign *(recommended — see rationale below)*

**Everything in Option A, plus: unify the two map engines' visual language (not necessarily their code) and fix the library's structural clutter. Simplify navigation and IA without rebuilding routes.**

- **Visual identity**: Same completed blue migration as Option A, plus a genuine shared "map" visual grammar: pick one node/connector/selection treatment and apply it to both `MindElixirView.jsx` and `StudyMapView.jsx`'s `MARK` constants, so a mind map and a study map read as dialects of the same visual language even though they stay on separate rendering engines (`mind-elixir` vs `react-d3-tree`) — this is the "Very High" migration-risk item (UX-ADJ-008) scoped down to its visual-parity slice only, deferring a true engine unification to Option C.
- **Navigation model**: Same fix as Option A for the missing study-library link, but go further: give the workspace header a persistent, always-visible "Thư viện học tập" entry (not just a relabeled dropdown), and audit-confirmed-legitimate contextual shortcuts (`05-duplication-matrix.md`'s "keep" verdicts for Chat/MindMap/Summary/Appearance/Export duplication) stay exactly as-is — this redesign does not remove a single shortcut the duplication matrix validated as useful.
- **Key layout changes**: Collapse `DocumentList.jsx`'s repeated-card sections (UX-ADJ-007, the 823-control problem) into one canonical result list with compact "Continue," "Needs quiz," etc. modules that filter/scroll to that one record, exactly as `05-duplication-matrix.md` recommends — this is the single highest-leverage structural fix in the whole audit, independent of the map-engine question. Everything from Option A's toolbar/overlay/breadcrumb/touch-target fixes carries over unchanged.
- **Advantages**: Closes the two most-cited "clutter" and "accumulated patches" complaints (library card repetition, map visual mismatch) without the very-high-risk, multi-week engine unification. Keeps all audited "legitimate shortcut" verdicts intact, so familiar workflows for existing users don't move.
- **Disadvantages**: Users will still notice two different interaction models (editable mind-elixir canvas vs. read-only d3 SVG) even after visual parity — this option narrows the seam, it doesn't close it.
- **Cost/complexity**: Medium. The card-list consolidation touches `DocumentList.jsx`/`StudyCard.jsx` directly (both audits flag this as a multi-file, non-trivial but contained change) and carries Medium-High regression risk per the duplication matrix (sections, selection, analytics, and scroll anchors currently assume repeated cards) — needs its own before/after screenshot gate, not a blind refactor.
- **Reuse of existing code**: High. No route changes, no state-management changes, no engine swap — `WorkspaceContainer`'s simultaneous-mount invariant and `useStudyContext`'s dual-identity contract (both guarded in `08` §6) are untouched.
- **Responsive strategy**: Same as Option A, plus explicit mobile verification of the consolidated card list (it must not reintroduce the 823-control problem at a different breakpoint).
- **Accessibility strategy**: Same as Option A, plus the consolidated card list must preserve `StudyCard.jsx`'s already-documented roving-tabindex pattern (a genuine strength noted in the prior `UI_AUDIT_V2.md` and not contradicted by this audit) rather than flattening it.
- **Risk**: Low-to-Medium. The one Medium-High item (card consolidation) is isolated to one feature area and has an explicit rollback path (the current repeated-card markup can be restored without touching any other screen).

**Why B is recommended**: it is the only option that directly answers the user's two most specific complaints — "Mind Map / Export Studio have accumulated multiple rounds of patches" (answered by finishing the blue migration + map visual parity) and "excessive visual clutter" (answered by the card-list consolidation) — without taking on the Very-High-risk map-engine unification that Option C requires, and without leaving genuine, audit-validated contextual shortcuts on the cutting-room floor the way a less careful "simplify everything" pass would.

## Option C — Structural redesign

**Everything in Option B, plus unify the Mind Map and Study Map into one graph engine and one route-level IA, closing the "two apps" seam completely.**

- **Visual identity**: One canonical graph visual language, one engine (most likely `mind-elixir`, since it already carries the richer feature set — editing, Export Studio, relations, Knowledge Inspector — that `react-d3-tree`'s read-only `StudyMapView` would otherwise have to rebuild from scratch).
- **Navigation model**: Collapse `/app` and `/app/study/*` into a single workspace-centric IA where "a map" is one concept with one entry point, one appearance system, one export pipeline — eliminating the `/app` vs `/app/study` route bifurcation that UX-ADJ-001 (missing nav link) was a symptom of, not just patching the symptom.
- **Key layout changes**: Migrate `StudyMapView.jsx`'s consumers (quiz result review, practice mode deep-links) onto the mind-elixir-based canvas in read-only/annotation mode; retire the separate `react-d3-tree` rendering path once migration is verified.
- **Advantages**: Fully resolves the "two map engines with zero interoperability" P1 (UX-ADJ-008) and the deeper IA confusion it causes — "a map of my knowledge" becomes genuinely one thing, matching the brief's primary success criterion ("StudyMap should feel like ONE coherent learning product").
- **Disadvantages**: `08`'s own guardrails flag this as **Very High** migration risk — `StudyMapView.jsx`'s rendering logic is hand-rolled and mixes visual constants with interaction logic (`onPick`/`toggleNode`/search-focus state) in the same functions, and `useStudyContext`'s stem-vs-UUID dual identity (guarded, do-not-touch per `08` §6) is load-bearing for exactly the routes this option would merge. A rushed version of this is the single most likely way to introduce a real regression.
- **Cost/complexity**: High-to-Very-High. Multi-week, needs its own isolated visual QA pass (same caution the prior `UI_AUDIT_V2.md` already called out for Mind-Elixir and StudyMapView individually, now doubled for the merge).
- **Reuse of existing code**: Moderate. The mind-elixir canvas, Export Studio, and appearance system are reused; `StudyMapView.jsx`'s bespoke SVG renderer is retired.
- **Responsive strategy / accessibility strategy**: Inherits whichever engine is kept — if mind-elixir, it inherits that engine's existing (already-audited, generally strong) responsive/keyboard/focus behavior, which is a net accessibility improvement over `StudyMapView`'s click-only SVG node selection (flagged as a real a11y gap with no keyboard path other than search-result jump).
- **Risk**: High. This is the only option that touches a guarded architectural invariant (`useStudyContext`'s dual identity) and requires a backend-aware migration (the UUID-vs-stem split is "baked into backend endpoints" per `08` §6), not a frontend-only change.

## Recommendation

**Ship Option B now.** It resolves every P0, every P1 except the engine-unification item, and the two complaints the user named most specifically (patch-accumulation feel, visual clutter) — with contained, mostly-Low/Medium risk and zero changes to guarded architectural invariants. Treat Option C's engine unification as a separate, explicitly-scoped future initiative once B has shipped and the library/map-parity changes have had real usage — not because it's wrong, but because bundling a Very-High-risk backend-aware migration into the same release as the P0 navigation fix increases the chance that nothing ships before the user's patience for "accumulated patches" runs out again.
